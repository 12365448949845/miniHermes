# Code Review

当用户提供代码（任何语言）时，自动对其进行 code review。

## 工作流程

1. 阅读用户提供的代码，理解其意图和上下文
2. 从以下几个维度进行分析：
   - 正确性：逻辑是否有 bug、边界条件是否处理、错误处理是否完善
   - 性能：是否有不必要的循环、重复计算、内存浪费、数据库 N+1 问题等
   - 可读性：命名是否清晰、结构是否清楚、是否需要注释
   - 安全性：是否有注入风险、敏感信息泄露、越权等问题
   - 工程规范：是否符合该语言的最佳实践和惯用写法（如 Go 的 error handling 惯例）
3. 输出 review 结果

## 输出格式

用纯文本（终端友好，不用 markdown）输出，结构如下：

[总体评价] 一句话总结代码质量

[问题与优化建议]
逐条列出，每条包含：
- 位置（哪行或哪个函数）
- 问题描述
- 具体优化建议或示例代码片段

[优点] 列出代码中做得好的地方（如有）

## 注意事项

- 如果代码很短或很简单，也要认真分析，不要敷衍
- 优先指出严重问题（bug、安全漏洞），其次是性能，再次是风格
- 给出的建议要具体可操作，避免泛泛而谈
- 用中文输出（除非用户用英文交流）
- 对 Go 语言代码，额外关注：goroutine 泄漏、context 传递、error wrap、defer 使用
